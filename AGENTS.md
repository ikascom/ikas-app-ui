# AGENTS.md

Guidance for AI coding agents working in this repository. Humans: see
[CONTRIBUTING.md](CONTRIBUTING.md).

This repo is a shadcn registry (`@ikas`) of React components for apps built on
ikas. It produces build output only (`dist/r`, `dist/manifest`, `preview/out`);
the docs site that serves it is a separate repo.

## Layout

| Path | Contents |
| --- | --- |
| `registry/theme.css` | All theme tokens (colors, radius, shadows, keyframes) |
| `registry/ui/*.tsx` | Primitives → `@ikas/<file name>`, installed to `components/ui` |
| `registry/ikas/*.tsx` | Screen patterns → `@ikas/<file name>`, installed to `components/ikas` |
| `registry/lib/*.ts`, `registry/hooks/*.ts` | Helpers → `lib/`, `hooks/` |
| `registry/rules/ikas-ui.md` | UI rules for app developers' agents (`@ikas/ui-rules`) |
| `demos/<name>/<variant>.tsx` | Demos, registered in `demos/index.ts` (or an `index-*.ts` spread into it) |
| `examples/*.tsx` | Full example screens, registered in `examples/index.ts` |
| `preview/` | Next.js preview app (static export, base path `/ui-preview`) |
| `scripts/` | `build-registry.mjs`, `build-manifest.mjs`, `build-thumbnails.mjs`, `check-content.mjs`, `smoke-install.mjs`, `health-check.mjs` |
| `registry.json` | Generated by `pnpm registry:build`. Never edit by hand; commit it. |

## Import aliases

Registry source uses the aliases every shadcn project has; `tsconfig.json` maps
them here and the shadcn CLI rewrites them on install.

| Import | Resolves to here |
| --- | --- |
| `@/components/ui/*` | `registry/ui/*` |
| `@/components/ikas/*` | `registry/ikas/*` |
| `@/lib/*` | `registry/lib/*` |
| `@/hooks/*` | `registry/hooks/*` |
| `@/demos`, `@/examples`, `@/preview/*` | `demos/`, `examples/`, `preview/components/*` (never import these from `registry/`) |

Registry files must only import other registry files (via the aliases above),
`react`, `next`, or npm packages. Dependencies are inferred from imports.

## Commands

```sh
pnpm dev               # preview app, http://localhost:3001
pnpm lint
pnpm typecheck
pnpm check:content     # no internal hosts, internal app names or brands in samples
pnpm registry:build    # registry.json + dist/r
pnpm registry:validate
pnpm manifest:build    # dist/manifest (needs registry.json)
pnpm build             # registry + manifest + preview + thumbnails
pnpm thumbnails:build  # dist/thumbnails from preview/out (needs Chrome; skips without it)
pnpm smoke             # install all items into the ikas starter app + tsc (needs dist/r)
pnpm health            # shadcn Registry Health mirror: dry-run install of every item (needs dist/r)
pnpm changeset         # add a changeset
```

## Rules

- Theme tokens live only in `registry/theme.css`. Components use token classes
  or `var(--token)`; no hex/rgb/oklch literals in components, demos or examples.
- Every demo file must be registered in `demos/index.ts` (id = path without
  `.tsx`, e.g. `"page/simple"`). Every example must be registered in `examples/index.ts`.
- Export components and their props types by name: `export { Thing, type ThingProps }`.
  Document each own prop with JSDoc; defaults go in the destructuring.
- Item names, `/r/{name}.json` and `/ui-preview` paths, CSS token names and
  exported prop names are a permanent contract. Deprecate with `@deprecated`
  JSDoc for at least one minor release before removing; for an incompatible
  redesign create a new item (e.g. `record-table-v2`).
- Sample content stays generic: no real store, app, marketplace or brand names.
- Every registry item needs an entry in `meta` (`scripts/build-registry.mjs`):
  a description of at most 15 words and 1–2 categories from `CATEGORIES`.
  `pnpm registry:build` fails otherwise.
- Before opening a PR run the "Before you open a PR" checklist in
  CONTRIBUTING.md, commit `registry.json`, and add a changeset.
